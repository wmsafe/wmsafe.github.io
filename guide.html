BEFORE YOU START

开始前的准备

两端先完成终端登录，并核对资源凭证和业务可用性。

A

A 端 / Provider 发布端

确保发布主机能够访问目标内网业务，明确真实 IP、服务端口、Link ID 以及专用通信口令。

B

B 端 / Visitor 访问端

获取发布端交付的同一条资源的 Link ID 与通信口令，选择当前电脑空闲的本地端口。

STEP BY STEP

标准操作流程

根据官方用户指南 V1.04 整理，细节以配套 PDF 页面为准。

  1. 登录终端

    输入管理员分配的终端账号与安全凭证，连接中心网关。

  2. 发布指定业务

    在 A 端开启服务发布，配置真实内网 IP:Port、业务名称和资源凭证，保存并运行。

  3. 交付资源凭证

    将对应的 Link ID 与通信口令通过可信渠道交付授权使用者。

  4. 新增访问规则

    在 B 端输入对应凭证，选择本地 IP、空闲端口以及 HTTP/HTTPS、TCP 或 RDP 协议类型；RDP 可配置 Windows 登录信息。

  5. 保存并开始访问

    启动安全引擎后，在工作台按协议使用资源：Web 点击“浏览器打开”，RDP 点击“进入远程桌面”，原生 TCP 使用相应客户端连接本地端口。

发布端与访问端的端口分别配置

示例：A 端真实业务为 192.168.28.1:3001，B 端本地映射为 127.0.0.1:8888。用户实际访问后者。

COMMON QUESTIONS

常见疑问

以下内容依据用户使用说明书整理。

终端账号与 Link ID 是同一回事吗？

两套凭证用途不同：终端账号和安全凭证用于客户端登录；Link ID 与通信口令用于特定业务的访问授权。

什么时候使用 127.0.0.1？

普通个人使用推荐 127.0.0.1，仅让本机程序连接映射入口。

什么时候使用 0.0.0.0？

仅在需要从其他设备访问本机映射端口、且网络和防火墙受控的情况下使用。

登录成功，但业务打不开怎么办？

依次确认原始业务正常、发布端在线、Link ID 与口令一致、访问端本地端口空闲、协议类型正确。

网页和 SSH/RDP 是否相同操作？

网页类业务在工作台用浏览器快捷打开；RDP 通过工作台直接调用 Windows mstsc；SSH、数据库等原生 TCP 业务使用对应客户端连接本地端口。
